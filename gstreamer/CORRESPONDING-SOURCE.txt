================================================================================
 Corresponding source code - GStreamer 1.28.6
 Where to get it, and why KVRouite does not host it
================================================================================

WHAT KVRouite DISTRIBUTES
-------------------------
The Windows build of KVRouite contains the prebuilt GStreamer binaries from the
"gstreamer-bundle" 1.28.6 wheels on PyPI. Those wheels are published by the
GStreamer Project itself (see the "Author: GStreamer Project" field in their
package metadata); they are the same binaries the project ships in its official
Windows and macOS installers.

KVRouite does not compile, patch, rebuild or otherwise modify any of them. They
are passed on byte for byte, exactly as pip installs them.

These are the only third-party binaries this application ships, so the
arrangement below covers all of them.

WHY THERE IS NO SOURCE ARCHIVE ON kvrouite.com
----------------------------------------------
Every GPL component here is licensed GPL-2.0-or-later, and every LGPL component
LGPL-2.1-or-later. The "or later" lets the distributor convey them under version
3 of the respective license, and KVRouite - being GPL-3.0-or-later as a whole -
does exactly that.

GPL version 3, section 6(d) covers this case directly. When the object code is
offered from a network server (for KVRouite: the GitHub Releases page), the
Corresponding Source may sit on a different server, operated by a third party,
as long as clear directions next to the object code say where to find it. This
file, together with NOTICE.txt, is those directions. LGPL version 3 adopts the
same conveyance terms.

The Corresponding Source for these binaries is published by the GStreamer
Project on its own servers, in the same version, and is therefore already
available under exactly the conditions section 6(d) requires. Copying it onto
kvrouite.com would add nothing.

WHERE THE SOURCE IS
-------------------
Release tarballs, version 1.28.6, at https://gstreamer.freedesktop.org/src/ :

  https://gstreamer.freedesktop.org/src/gstreamer/gstreamer-1.28.6.tar.xz
  https://gstreamer.freedesktop.org/src/gst-plugins-base/gst-plugins-base-1.28.6.tar.xz
  https://gstreamer.freedesktop.org/src/gst-plugins-good/gst-plugins-good-1.28.6.tar.xz
  https://gstreamer.freedesktop.org/src/gst-plugins-bad/gst-plugins-bad-1.28.6.tar.xz
  https://gstreamer.freedesktop.org/src/gst-plugins-ugly/gst-plugins-ugly-1.28.6.tar.xz
  https://gstreamer.freedesktop.org/src/gst-libav/gst-libav-1.28.6.tar.xz
  https://gstreamer.freedesktop.org/src/gst-editing-services/gst-editing-services-1.28.6.tar.xz
  https://gstreamer.freedesktop.org/src/gst-python/gst-python-1.28.6.tar.xz
  https://gstreamer.freedesktop.org/src/gst-rtsp-server/gst-rtsp-server-1.28.6.tar.xz
  https://gstreamer.freedesktop.org/src/gst-devtools/gst-devtools-1.28.6.tar.xz

Each tarball is accompanied by a .sha256sum and a .asc signature file on the
same server. The archive is a full historical one - it still carries releases
going back to 2002 - so these links are expected to keep working.

The scripts that turn these sources into the exact binaries in the wheels (the
build recipes, toolchain and patches) are the "cerbero" build system, published
by the GStreamer Project at https://gitlab.freedesktop.org/gstreamer/ .

The wrapped third-party libraries listed in COMPONENTS.txt - x264, x265,
FFmpeg 7.1, liba52, libdca, libdvdread, libdvdnav and the permissively licensed
ones - are fetched from their own upstream projects by those same recipes,
which name the exact version and checksum of each.

WHY POINTING IS ENOUGH HERE
---------------------------
Everything shipped here is licensed "or later" - LGPL-2.1-or-later for
GStreamer itself, GPL-2.0-or-later for the x264, x265, a52dec, dtsdec and
dvdread plugins. KVRouite conveys them under version 3, and GNU GPL version 3
section 6(d) expressly allows the Corresponding Source to sit on a different
server, operated by a third party, as long as clear directions next to the
object code say where to find it. Those directions are this file.

KVRouite compiles none of this. The binaries are the GStreamer Project's own
official wheels, redistributed byte for byte, so the Corresponding Source is
that project's own published release - the same source anyone can fetch from
the addresses above.

What section 6(d) does ask of us is that the directions keep leading somewhere.
If a link above no longer works, or if a future release should withdraw version
1.28.6, write to:

  bernd@kvrouite.com

and you will be pointed at a working source for the version you received.

FOR MAINTAINERS
---------------
Before publishing a Windows release that contains GStreamer:

  [ ] requirements.txt, NOTICE.txt, COMPONENTS.txt and this file all name
      the same version.
  [ ] The download links above still resolve, and they point at that version.
  [ ] build_with_pyinstaller.py printed "GStreamer WIRD mit ausgeliefert" and
      "Rechtstexte liegen in _internal/gstreamer - OK."
  [ ] The build is not a single-file executable (LGPL section 6: the DLLs must
      stay replaceable).
